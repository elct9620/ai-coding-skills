# Naming

A reader learns the structure from the names before reading any logic.

| Check | Holds when |
|---|---|
| One word, one meaning | A word names one concept across the scope |
| One meaning, one word | A concept carries one name; synonyms are findings |
| Matches the project | The name follows the project's naming convention, or how the surrounding code names the same kind of thing |
| Carries the intent | The name says why it exists; a comment restating the code means the name falls short |
| Vocabulary of its context | Directories and types use their context's words, not `models/`, `utils/`, `manager` |

Across contexts, the same real-world thing takes the name of its role there — a `Customer` in sales, a `Recipient` in shipping.
